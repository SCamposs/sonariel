# Sonariel v0.4.0-rc.1 — test prerelease

[Português (Brasil)](v0.4.0-rc.1.pt-BR.md)

Public test candidate for the proposed v0.4.0, **not a stable release**. The official download/update remains v0.3.2. Do not install this candidate over a production installation or open a production profile during acceptance.

## Included since v0.3.2

- English and Brazilian Portuguese UI, language selection and workflow guidance.
- Batch WAV export with verified copies, collision handling and optional portable metadata.
- Versioned music presets with explicit review before generation.
- Non-destructive reference/source excerpts with engine/role validation, hashes and lineage.
- Project-specific tags, combined persistent library filters and incremental card rendering.
- Workspace scroll isolation and FX draft retention during module navigation.
- Atomic schema upgrades with consistent backups and recovery tests.
- Development-build protection against overwriting a running runtime.

## Availability and limits

Loop creation is **unavailable in packaged distributions**, excluded from MCP discovery and rejected by the core. Existing loop WAVs, jobs, recipes and lineage are preserved and remain readable/exportable. Previously queued loop jobs are interrupted with an explicit unavailable message before DSP starts. Other FX and reference excerpts remain available. Issue #3 remains open after two rejected musical listening rounds.

Source development can explicitly enable loop experiments with `SONARIEL_DEVELOPMENT_LOOPS=1` and a separate profile outside the stable data tree. That environment setting cannot enable loops in the packaged candidate. This is a capability boundary in Sonariel, not an OS sandbox for the standalone DSP binary.

CPU profiles, RAM gates and model terms are unchanged. Stable Audio and Chatterbox retain their documented experimental limits. No GPU, active inference cancellation, SFT, MP3 or guaranteed musical loop continuity is introduced. Models are not bundled. A/B selection and unsaved FX drafts are temporary desktop state. Audacity remains optional and requires a compatible separately prepared installation.

Schema 3/4 profiles receive a consistent backup before migration to schema 5. Old cores refuse newer schemas; automatic downgrade is not supported. Preserve the WebView profile during a real installation upgrade. Tauri update signing is separate from Windows Authenticode; an unknown-publisher warning remains possible.

SemVer identity is `0.4.0-rc.1`; Python package metadata uses the equivalent PEP 440 form `0.4.0rc1`. Native Windows numeric version fields may omit the prerelease suffix; installer filename, application UI, core handshake and authenticated updater version identify the RC.

**Windows clean installation and v0.3.2 installer upgrade are still pending validation.** This prerelease is published to enable those VM tests. Installation, update and release readiness are recorded separately in the Phase 2.7 acceptance report. Passing unit tests is not a clean-install or installer-upgrade claim. Publication requires the owner's explicit authorization.
